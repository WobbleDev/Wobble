# Route table (B01, reconciled)

Source: spec §3. Every row was checked against the handler in the **Source** column on
`migration/tauri`, after the D3 header migration (A03/A04).

Error convention: body `{message}`; the Worker edit flow's routes and the ticket-05 data
controls (`GET /api/data-file`, `POST /api/restore`, `POST /api/erase`) add a stable
`code` beside it (as recorded in the local decision records); 400 invalid
input · 404 not found · 409 no Active Worksite.
A malformed request body is always 400 `"Request body must contain valid JSON."` (read-json-request.ts).
The Active Worksite comes from the `x-wobble-worksite` header; absent/unknown falls back to the
first Worksite, and there is no Active Worksite only when the table is empty.

## Reconciliation notes (differences from the draft / briefing)

1. **Worker `PUT`/`PATCH`/`DELETE` return 404, not 409, with no Active Worksite.** The briefing
   expects 409. `updateWorker`, `updateWorkerAssessment` and `deleteWorker` take
   `Worksite | null` and report `not-found`; only `POST /api/workers` checks the Worksite
   explicitly and returns 409.
2. **`GET /api/agitations`, `GET /api/languages` and `GET /api/settings` never 409.** The two
   list reads pass the nullable Worksite to `getAgitations`/`getLanguages`, which return `[]`;
   settings does not touch the Worksite at all.
3. **`POST /api/worksite` and `DELETE /api/worksite` do not activate anything server-side.** Under
   D3 the reply carries the created Worksite / the survivor (or `null`), and the client stores the
   id and sends it on the next request. `PUT /api/worksite/active` likewise validates only.
4. **A decode 400 wins over a 409 on the worker routes.** `PUT` runs `decodeWorkerUpdate` before it
   touches the Worksite, and `PATCH` runs `decodeWorkerPatch`; an invalid body is 400 even with no
   Active Worksite.
5. **Cross-Worksite ids in the replace routes are uncaught throws (`agitation-persistence.ts`,
   `language-persistence.ts`, `attribute-persistence.ts`), i.e. a SvelteKit 500**, not the
   400/409 the draft lists. Crafted-only (normal clients never send a foreign id); recorded here
   rather than changed.
6. **`POST /api/backup` is Rust-only and finished (F01).** It copies the live database to a path
   the caller names and never moves the original; the client reaches it from Settings → Backup in
   the desktop shell. The dev shim answers 501 for it, because a browser cannot name a filesystem
   path (E02).
7. **`GET /api/data-file`, `POST /api/restore` and `POST /api/erase` are Rust-only (ticket 05).**
   They have no Node recorder. Restore and Erase answer through the core, so the dev shim serves
   them too; the settings e2e drives them directly against its own database.
